and permit All (122). The cause is Jwt Authentication Filter: when an auth cookie is
present, the filter validates it; for an **ADMIN** token it checks the Redis session
allowlist session:admin:`<session Id>` (Jwt Authentication Filter implementation reference). If that
session key is absent it calls the send unauthorized operation → **401 that short-circuits the whole
filter chain — on EVERY endpoint, including public permit All ones.** The dev backend was
redeployed several times this session, which flushed/rotated Redis, so the founder's
session:admin:a1b63b38-... no longer exists → every request carrying that cookie 401s,
forgot-password included. (The signed session token itself was still within its exp window — not an expiry
issue; it's the session-allowlist miss.) Same shape applies to TUTEE/TUTOR if their jti
is on the denylist (80-85).

**Blast radius confirmed across ALL public auth endpoints (bodies prove it's the filter,
not creds/validation):**

The UNAUTHORIZED / Authentication required body (vs INVALID CREDENTIALS / VALIDATION ERROR)
