## 7. Notes

### 7.1 Meeting Link Storage

meeting link is stored as a plain the varchar operation. It is NOT encrypted at rest because:
- Meeting links are not personal information under Personal Data Protection Act
- The link is a time-limited URL generated by a third-party service (Zoom/Meet/etc.)
- Both tutee and tutor receive the link via email notification — it is "known" information

If the agency later adopts a policy of encrypting all external links for audit purposes, this can be revisited. For MVP, plain storage is sufficient.

### 7.2 admin notes Field

admin notes is a free-text field for internal admin coordination notes (e g., "Tutor preferred Saturday morning only. Rescheduled once."). It is admin-only and not returned in tutee or tutor application programming interface responses.

### 7.3 No Hard Delete

Interview records are retained even after terminal states. This supports:
- Cooldown enforcement (query for COMPLETED/NO SHOW within 30 days)
- Analytics (conversion tracking)
- Audit trail

Admin has no delete action on interview records in the user interface.

### 7.4 automatically remove dependent records — Caution

Both tutee id and tutor post id use automatically remove dependent records. This has an important consequence for the **30-day cooldown guard**: if a tutor post is soft-closed (status = CLOSED) but not hard-deleted, cooldown history is preserved. However, if the tutor post row is physically deleted (e g., admin hard-deletes a spam post), all associated interview records — including COMPLETED and NO SHOW records — are silently removed. This means a tutee's cooldown for that post vanishes.

**Preferred approach:** Tutor posts should use soft-delete (status transition to CLOSED/EXPIRED) rather than hard-delete in normal operation. Hard-delete should only occur during Personal Data Protection Act erasure flows.

**Personal Data Protection Act erasure flow:** The anonymization job must process interview records before running remove records from users or remove records from tutor posts:
1. Replace tutee id with anonymized hash
2. Replace tutor post id with anonymized hash
3. Null out meeting link, admin notes, cancellation reason, note
4. Then allow CASCADE to remove the user/post row (interviews already anonymized and decoupled)

If the erasure requirement is immediate deletion (not anonymization), interview records will CASCADE-delete — this is acceptable under Personal Data Protection Act right of erasure, but analytics derived from those records become orphaned. The analytics team should ensure aggregates are computed before erasure runs.
